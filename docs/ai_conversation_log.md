## 2. 有效问答整理（按主题）

### 主题 A：训练流程与原理

**Q：解释一下是怎么训练、怎么标记、流程是什么、为什么要这么做？**

A（要点）：
- (A) Baseline：3634 个标注视频监督训练，`MSE(预测分 − 人工MOS)`；909 验证集锁定只评估不训练
- (B) 半监督：把 909 验证视频当"无标注"，模型自己预测造伪标签扩充训练集。每轮：
  1. B.1 伪标签生成——从 baseline 出发做 5 次独立训练-打分（不同随机子集），均值=伪MOS、方差=置信度，方差小于阈值才入池
  2. B.2 验证微调——用「真标注(w=1.0)+伪标签池(w=0.5)」再训 10 epochs，锁定验证集上算指标，超过 best 存权重
- 设计动机：真实标注贵（人工打分）；5 次投票抗噪声；方差筛选挡噪声标签；权重 0.5 防止过度相信自己的错误；每轮从 baseline 重新出发防错误累积；早停防浪费算力

### 主题 B：指标含义

**Q：OBJ 和 PLCC 下降是什么意思，代表模型对打分的性能没有提升还是什么意思？**

A（要点）：
- PLCC = 预测值与真值的线性相关（数值准不准）；SROCC = 排序一致（顺序对不对）；OBJ = 两者之和
- 半监督各轮"SROCC 稳、PLCC 崩"= 模型排序能力没丢，但输出的具体分数被伪标签带偏，数值标定破坏
- 类比：学生拿自己的答案当标准答案反复背——越背越自信，数值越离谱，但顺序不乱
- 最终交付取所有 checkpoint 中 OBJ 最高者，不无条件用最后一轮

### 主题 C：半监督实验失败与数据诊断（核心方法论链条）

**Q：这轮完成后，对当前数据进行解释，然后写汇报文档，再修改数据后进行下一轮测试。**

A（完整诊断，详见 `docs/semisup_experiment_report.md`）：
1. **分布压缩**：伪标签 std=0.422 vs 真标注 0.491——模型"不敢打低分"（伪最低 1.817 vs 真 1.213），"够得着超高分"（伪最高 5.370 越出 1~5 量纲）
2. **分段偏差被巧合掩盖**：低分视频高估 +0.559、高分视频低估 −0.157，整体偏差仅 +0.025——均值抵消假象
3. **两个放大器**：方差阈值 0.2 形同虚设（905/909 全过）；伪标签权重 0.5 太激进
4. **根因**：伪标签是模型自身预测的复制品，压缩偏差以 0.5 权重回喂 → 模型学会"把分数往中间挤"→ PLCC 崩、SROCC 稳

**修改方案**（全部落地为新命令行参数）：
| 修改 | 原值 | 新值 |
|---|---|---|
| 伪标签 z-score 重标定（对齐真标注分布） | 无 | `--pseudo-debias` |
| MOS 裁剪到 [1,5] | 无 | `--pseudo-clip` |
| 伪标签权重 | 0.5 | 0.2 |
| 方差阈值 | 0.2 | 0.05 |

**结果**：v2 轮次 1 仍降（1.2800）→ 轮次 2 反超（1.3457 > 1.3446），重标定后 PLCC 崩盘消失。说明"数据诊断→修正→复测"的方法论闭环有效。

### 主题 D：模型能力边界

**Q：模型可以识别阐释哪些视频质量问题？**

A（完整分析见 `docs/summary_report.md`，关键结论）：
- 架构关键事实：每帧独立提特征 + 时间维**平均池化**（对帧顺序置换不变）
- 能识别（强）：模糊、压缩块效应/振铃、噪声（std 池化直接编码）、曝光异常、偏色、低频亮度闪烁（合成闪烁自测 SROCC≈0.92 证实）
- 部分识别（弱）：中高频闪烁（8 帧采样混叠）、冻结/丢帧（均值池化无法感知重复性）
- 结构性盲区：运动平滑度/抖动（无光流/帧差特征）、帧间内容不一致但每帧正常（置换不变性）、音频、分辨率差异（统一 224）
- 一句话定位：本质是"逐帧空间失真回归+时间平均"，打分的是"平均一帧有多烂"，不是"视频动起来是否连贯"——时域维度恰是薄弱点

### 主题 E：模型定位

**Q：我用的模型是参考任务书里的论文复现的成熟模型吗？**

A：组件是成熟论文复现（ResNet-50[文献1]、ViT-B/16[文献2]、多尺度统计池化来自 ReLaX-VQA[文献3]、TSN 抽帧[文献4]、时间平均聚合来自 Patch-VQ[文献5]），骨架用官方 ImageNet 预训练权重；整体是任务书第五章规定的组合架构（13568+2304=15872 逐维对齐），非照搬某个现成端到端模型。与 SOTA 的差距诚实可述，见主题 F。

### 主题 F：与 GitHub 模型的取舍

**Q：如果我在 GitHub 复现模型是不是比这样更快且更准确？**

A：纯性能——是，成熟模型（尤其 ReLaX-VQA 原版，就是在 MaxWell 上评测的）更准且有现成权重；课程场景——不建议换主线（任务书指定架构、课程设计价值在自建全链路）；结论：主线不动，SOTA 做对照实验加分。用户随后决定"选择最新的成果复现"→ 选定 CAMP-VQA。

### 主题 G：分工与接口设计

**Q：我分了三部分（噪点、闪烁、模糊）交给组员分别做，留出接口方便合成。**

A：设计统一接口 `vqa/diagnosis.py`：
- 三槽位 `NOISE_DETECTOR` / `FLICKER_DETECTOR` / `BLUR_DETECTOR`，统一约定 `detect(frames_rgb) -> {score:0~1, level:无/轻/中/重, detail:{}}`
- 检测器只吃抽帧结果，**不依赖打分模型**——组员可并行开发自测
- 整合入口 `scripts/diagnose.py`：问题清单 + 可选挂主模型总分 → `report.json/txt`，与 `score.txt` 配套
- 三部分与整体打分近似独立，这正是接口设计的意图

## 3. 关键结论速查（可直接引用）

1. 任务书架构在课程数据上 baseline SROCC/PLCC=0.6723，合成闪烁自测 0.92
2. 伪标签法默认配置无效（四轮全低于 baseline），根因=伪标签压缩偏差+权重过大；修正配置（重标定+0.2+0.05）后轮次 2 反超 baseline
3. 模型能力边界：空间失真敏感、时域维度结构性薄弱（均值池化置换不变），后续方向：时域差分特征/光流分支/时序注意力
4. SOTA 对照：CAMP-VQA（WACV 2026，MaxWell 作者组）复现管道已就绪
5. 分组协作：组长整体打分（A+B 全流程），三组员各做一类失真判定，接口统一合成

**要点**：长时间训练前把 stdout 重定向到文件；Windows 关终端 ≠ 杀进程，恢复时先查 `tasklist`；checkpoint/池状态每轮落盘才能最小化中断损失。
