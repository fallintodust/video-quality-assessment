# 特征缓存方案（冻结骨干 + 回归头）

本文档说明 `scripts/extract_feats.py`、`scripts/train_head.py`、
`scripts/predict_head.py`、`scripts/app.py` 这一条流程的设计取舍与实测结果，
与仓库中原有的端到端方案并行存在，不冲突。

---

## 1. 为什么不端到端训练

任务书参考方案要求特征提取器与回归头联合训练。实际执行时遇到硬件约束：

- 显卡：RTX 3050 Ti Laptop，**显存 4 GB**
- ResNet-50 + ViT-B/16 在 T=32 帧下端到端反向传播放不下

因此改为：**骨干网络冻结，只训练回归头**。骨干等价于固定的特征提取器，
一次性把每个视频的逐帧特征算出来存盘，之后所有实验直接读缓存。

带来的直接好处：

| | 端到端 | 特征缓存 |
|---|---|---|
| 单次实验耗时 | 数小时 | 数十秒 |
| 显存需求 | > 8 GB | < 2 GB |
| 消融实验成本 | 每组重跑全流程 | 复用同一份缓存 |

代价是骨干不再针对本任务微调，指标上限会低一些。这是在 4 GB 显存下的
现实选择，报告中需如实说明。

---

## 2. 抽帧方式：连续片段而非全局均匀

任务书方案是在整段视频上均匀抽 T 帧（TSN 式）。本方案改为
**K 个片段、每片段 L 帧连续帧**（默认 K=4, L=8，共 32 帧）。

理由有二：

**（1）时域一致性需要相邻帧。** 数据集视频帧数中位数为 270。若均匀抽 16 帧，
相邻两帧在时间上相隔约 17 帧（约 0.5 秒）。这样两帧之间的差异反映的是
**场景运动**，而不是**闪烁**。闪烁是逐帧级别的现象，只有在连续帧上才能观测到。

**（2）解码开销。** h264 随机定位需要回退到最近的关键帧重新解码。
K 次定位比 T 次定位快得多。实测在本机上单视频解码约 1.40 秒。

帧数不足的视频（数据集中最短的只有 5 帧）用最后一帧重复补齐。

## 3. 特征构成

单帧特征维度 **15872**，与任务书参考方案一致：

**卷积分支（ResNet-50）→ 13568 维**
- layer1~layer4 各自做 mean / max / std 空间池化：3×(256+512+1024+2048) = 11520
- layer4 的全局平均池化：2048
- 合计 13568

**ViT 分支（ViT-B/16）→ 2304 维**
- 最后一层 token 序列做 mean / max / std 池化：3×768 = 2304

逐帧特征以 float16 存为 `.npy`，形状 `[32, 15872]`，
单个视频约 1 MB，全库 4543 个视频约 4.6 GB。

**关键点：存的是逐帧特征，不是时间平均后的向量。** 这样后续可以在同一份
缓存上尝试任意时间聚合方式，无需重新解码。

---

## 4. 时间聚合方式（消融重点）

`train_head.py --agg` 支持三种，可用 `+` 组合：

| 模式 | 含义 |
|---|---|
| `mean` | 沿帧维求均值（任务书方案，baseline） |
| `std` | 沿帧维求标准差，反映时间上的波动幅度 |
| `diff` | **片段内**相邻帧特征差的绝对值均值 |

`diff` 的计算只在片段内部进行，不跨片段边界——不同片段的帧在时间上相距很远，
它们之间的差反映的是场景切换而非闪烁。

需要指出：`mean` 是对帧顺序不变的运算。把帧倒序输入，输出完全相同。
对于评价"时域一致性"的任务，这在原理上是一个缺陷。`std` 与 `diff`
是为弥补这一点而加入的。

## 5. 计算量核算

用 `thop` 实测（224×224 输入，单帧）：

```
python3 scripts/extract_feats.py --flops
```

| 配置 | 单帧 | 20 帧 | 是否满足 300G 限制 |
|---|---|---|---|
| ResNet-50 + ViT-B/16 | 20.98 GMACs | **419.6 G** | 否 |
| ResNet-50 + ViT-S/16 | 约 8.7 GMACs | 约 174 G | 是 |
| 仅 ResNet-50 | 约 4.1 GMACs | 约 82 G | 是 |

**任务书的参考架构本身超出了任务书给出的计算量限制。** 若按"输入 20 帧
全部参与计算"的严格口径，双分支方案不合规；若按"模型实际处理的帧数"
口径（例如从 20 帧中只取 8 帧推理），则 173.6 G，合规。

这一点需要向老师确认。在确认之前，可用 `--branch r50` 训练单分支模型作为
合规备选。

耗时方面不构成约束：本机推理约 1.4 秒/视频，100 个视频约 2.3 分钟，
距离 20 分钟的扣分门槛有 5 倍余量。**真正的约束是计算量，不是时间。**

## 6. 实测结果

验证集：`train_lable_test.txt`，909 个视频。骨干为 ResNet-50 + ViT-B/16。
下表可由 `python3 scripts/make_table.py --json runs/<轴>/results.json` 直接生成。

### 6.1 三轴对照

在同一份特征缓存上，只更换标注文件，训练回归头。骨干 ResNet-50 + ViT-B/16，
抽帧为 4 个片段 x 8 连续帧。

| 标注轴 | 时间聚合 | SROCC | PLCC | Score | 最优轮 |
|---|---|---|---|---|---|
| O（整体 MOS） | mean | 0.6950 | 0.7066 | **0.7008** | 27 |
| O（整体 MOS） | mean+std+diff | 0.6811 | 0.6903 | 0.6857 | 53 |
| T-5（stable/shaky，抖动） | mean | 0.6082 | 0.6039 | 0.6060 | 9 |
| T-5（stable/shaky，抖动） | mean+std+diff | 0.6800 | 0.6821 | **0.6811** | 40 |
| T-8（fluent/choppy，卡顿） | mean | 0.4349 | 0.4365 | 0.4357 | 6 |
| T-8（fluent/choppy，卡顿） | mean+std+diff | 0.4806 | 0.5206 | **0.5006** | 42 |

### 6.2 主要结论：时间特征的增益随标注轴的"时域性"单调上升

| 标注轴 | mean | mean+std+diff | 变化 | 相对 |
|---|---|---|---|---|
| O（整体质量） | 0.7008 | 0.6857 | -0.0151 | -2.2% |
| T-5（抖动） | 0.6060 | 0.6811 | **+0.0750** | **+12.4%** |
| T-8（卡顿） | 0.4357 | 0.5006 | **+0.0649** | **+14.9%** |

三条轴排成一条清晰的序列：**标注轴越偏时域，时间特征越有用。**

- **O 轴**衡量综合主观质量，主要失真（清晰度、噪声、曝光、构图）在单帧上
  即可判断，时间维度不提供新信息。变化 -0.0151 与噪声上界 0.011 同量级，
  判定为"无增益"。
- **T-5 轴**描述画面抖动，增益 +12.4%，约为噪声上界的 7 倍。
- **T-8 轴**描述播放卡顿，增益 +14.9%，是三者中相对增益最大的——
  卡顿本质上就是帧间时序的断裂，单帧完全看不出来。

同时，**任务的绝对难度也随时域性上升**：仅用 mean 时，
O 轴可达 0.7008，T-5 降到 0.6060，T-8 只有 0.4357。
这与均值聚合的性质一致——它对帧顺序不变，把帧倒序输入结果完全相同，
因此原理上无法感知任何时域现象；之所以还能得到非零相关，
是因为时域失真与画面整体质量本身存在相关性。

### 6.3 构造纯时域目标（tcons）与决定性验证

**问题：MaxWell 没有"闪烁"这一轴。** 任务书要求评价 时域一致性 与 闪烁，
但数据集的 16 个轴里最接近的只有 T-5（stable/shaky，摄像机抖动）和
T-8（fluent/choppy，播放卡顿），都不是严格意义上的亮度闪烁。

更麻烦的是这两轴被画面整体质量污染：抖动的视频往往同时被评为更模糊、更噪。
把时域混合（T-5 与 T-8 各自 z-score 后求平均）对纯单帧轴
（T-1 锐利、T-2 对焦、T-3 噪点、T-6 曝光、T-7 压缩）做最小二乘回归，
在训练集上得到：

```
R^2 = 0.441
```

**即"抖动/卡顿"有 44% 可以由单帧画质解释。** 这意味着模型只要读单帧线索，
就能在 T-5 上拿到相当高的分数，而完全不看时间。

`scripts/make_temporal_target.py` 取回归残差作为新目标（记为 tcons），
即单帧轴无法解释的那部分。残差与各轴的 Spearman 相关（训练集）：

| 轴 | 与 tcons 相关 |
|---|---|
| T-5（抖动） | **+0.663** |
| T-8（卡顿） | **+0.618** |
| T-1 锐利 | +0.005 |
| T-2 对焦 | +0.018 |
| T-3 噪点 | -0.007 |
| T-6 曝光 | +0.020 |
| T-7 压缩 | -0.003 |
| O 整体 | +0.236 |

与单帧轴的相关全部归零，与时域轴仍强相关——目标构造成功。

在这个目标上训练（骨干 r50，同一份特征缓存）：

| 时间聚合 | SROCC | PLCC | Score | 最优轮 |
|---|---|---|---|---|
| mean | 0.2619 | 0.2501 | 0.2560 | 44 |
| mean+std+diff | 0.4156 | 0.4322 | **0.4239** | 43 |

**增益 +0.1679，相对 +65.6%。**

两点值得注意：

**（1）`mean` 崩到 0.2560。** 它在 T-5 上能到 0.6060，靠的正是那 44% 的
单帧泄漏；堵住泄漏后，帧序不变的均值聚合几乎什么都看不到。
这直接证实了第 6.2 节的推断。

**（2）加入时间特征后性能翻了 1.66 倍。** 在这个目标上，
时间特征几乎是唯一的信息来源。

### 6.3.1 汇总：增益随目标"时域纯度"单调上升

| 目标 | 骨干 | mean | mean+std+diff | 变化 | 相对 |
|---|---|---|---|---|---|
| O（整体质量） | all | 0.7008 | 0.6857 | -0.0151 | **-2.2%** |
| T-5（抖动） | all | 0.6060 | 0.6811 | +0.0750 | **+12.4%** |
| T-8（卡顿） | all | 0.4357 | 0.5006 | +0.0649 | **+14.9%** |
| tcons（纯时域残差） | r50 | 0.2560 | 0.4239 | +0.1679 | **+65.6%** |

四个目标排成严格单调的序列：**目标越纯粹地反映时域现象，
时间特征的作用越大，从 -2% 一路升到 +66%。**
反过来，绝对分数单调下降（0.70 → 0.61 → 0.44 → 0.26），
因为单帧线索被逐步剥离，任务越来越只能靠时间信息完成。

这条曲线是本方案最主要的实验结论，也是对任务书参考方案
（均匀抽帧 + 均值聚合）最直接的反驳：
若课程标注确为时域维度，均值聚合会丢掉这条曲线右端的全部信息。

注：tcons 两行用的是 r50 单分支（见 6.6 节，ViT 分支无增益），
与前三行的 all 分支不完全可比；但每一行内部的对照都是同配置的，
增益的比较仍然成立。

### 6.4 实验波动

未固定随机种子，重复运行同一配置会有差异：

- `O + mean`（15872 维）：0.7011 / 0.7008，差异 **0.0003**
- `O + mean+std+diff`（47616 维）：0.6967 / 0.6857，差异 **0.0110**

高维配置的波动比低维大两个数量级，这本身也是过拟合的侧面证据：
47616 维特征只配 3634 个训练样本。判断效应是否真实时，
以观测到的最大波动 **0.011** 作为噪声上界。按此标准，
T-5 与 T-8 上的增益（0.065~0.075）是真实的，O 轴上的变化不是。

### 6.5 抽帧方式：最优选择取决于失真的时间尺度

在 T-5 轴上，把已训练好的模型分别喂给两种抽帧方式（200 个验证视频）：

| 抽帧方式 | SROCC | PLCC | Score |
|---|---|---|---|
| 全局均匀（TSN 式） | 0.6069 | 0.6303 | **0.6186** |
| 连续片段（4x8） | 0.5807 | 0.5976 | 0.5891 |

**这与本方案第 2 节的设计假设相反。** 原假设是"时域失真需要相邻帧"，
但在 T-5 上均匀抽帧反而更好，且不依赖模型——纯启发式检测器上
也是同一方向（0.2932 对 0.1851，见 `docs/flicker_detector.md`）。

原因在于时间尺度：T-5 的 shaky 指**摄像机抖动**，其周期在秒级；
而 8 帧片段在 30 fps 下只覆盖 0.27 秒，窗口太短，看不到抖动的完整周期。
均匀抽帧把 32 帧铺满整段视频，相邻样本间隔约 9 帧，正好落在抖动的尺度上。

注意这并不否定 `diff` 特征本身——在同为片段抽帧的条件下，
`diff` 在 T-5 上带来 +12.4% 的增益。真正的结论是：
**`diff` 应该在与失真时间尺度匹配的间隔上计算**，
而这个间隔对抖动（秒级）和卡顿（帧级）并不相同。

`extract_feats.py --sampling uniform` 可生成均匀抽帧的缓存，
用于验证"训练时也采用均匀抽帧"是否进一步提升（尚未做，需重新缓存约 105 分钟）。

### 6.6 分支消融：ViT 可以去掉

T-5 轴，`mean+std+diff`，同一份特征缓存：

| 分支 | 特征维度 | SROCC | PLCC | Score |
|---|---|---|---|---|
| r50（仅 ResNet-50） | 40704 | 0.6854 | 0.6815 | **0.6834** |
| all（双分支） | 47616 | 0.6800 | 0.6821 | 0.6811 |
| vit（仅 ViT-B/16） | 6912 | 0.6328 | 0.6326 | 0.6327 |

单用 ResNet-50 与双分支持平（差 0.0023，小于噪声上界 0.011），
ViT 单独明显更弱，且加进去没有增益。

**这直接解决了第 5 节的计算量问题：**

| 配置 | 单帧 | 20 帧 | 300G 限制 |
|---|---|---|---|
| ResNet-50 + ViT-B/16 | 20.98 GMACs | 419.6 G | 超出 |
| **仅 ResNet-50** | **约 4.1 GMACs** | **约 82 G** | **余量 3.6 倍** |

因此最终配置采用 `--branch r50`。无论老师按哪种口径核算计算量都合规，
第 5 节提出的口径问题也就不必再纠结。

### 6.7 对任务书参考方案的影响

任务书的参考方案是「全局均匀抽 T 帧 + 沿帧维求均值」，
同时又指明 MOS 描述的是**时域一致性**。上表显示这两者是矛盾的：
均值聚合恰好丢弃了时域信息。

若课程标注确为时域维度，则参考方案存在结构性缺陷，
本方案的连续片段抽帧 + `diff` 聚合可带来约 12% 的提升。
若课程标注为整体质量，则参考方案已足够，时间特征不必引入。

**这使得第 7 节的标注轴确认成为关键问题，而不只是格式细节。**

### 6.8 过拟合

四组实验均出现过拟合。以 T-5 + mean 为例，最优检查点在第 9 轮
（Score 0.6060），此后训练损失从 0.25 继续降至 0.029，
而验证指标回落并停在 0.59 附近。加入时间特征后最优轮推迟到第 40~53 轮，
说明更高维的特征需要更长训练，也更依赖正则化。

后续可尝试：增大 dropout 与 weight decay、提前停止、
或对 `diff` 分支单独降维后再拼接。

### 6.9 闪烁检测器：模型 vs 启发式

任务书要求的"闪烁"在 MaxWell 中没有对应轴（见 6.3 节）。
小组的 `vqa/diagnosis.py` 提供了三个失真检测槽位，闪烁槽由本人负责。
两种实现在 T-5 验证集（200 个视频）上的对比：

| 检测器 | SROCC | PLCC | Score | ms/视频 |
|---|---|---|---|---|
| 模型（缓存特征） | 0.5807 | 0.5976 | **0.5891** | 14 |
| 启发式 v2（均匀抽帧） | 0.2937 | 0.2928 | 0.2932 | 1750 |
| 启发式 v2（连续片段） | 0.2699 | 0.1003 | 0.1851 | 1312 |

模型接近启发式的两倍，因此 `FLICKER_DETECTOR` 槽位接入模型，
启发式保留为回退实现（torch 不可用或权重缺失时自动降级）。

启发式 v2 本身也比原基线有改进：原基线用相邻帧差均值，
无法区分闪烁与快速运动（两者帧差都很大）。v2 改用
**去趋势后的逐帧平均亮度波动**——闪烁会让整帧一起明暗变化，
运动则几乎不改变帧均值——再用 FFT 的谱集中度加权。
合成数据验证：

| 情形 | v2 score | 原基线依据的帧差 |
|---|---|---|
| 静态 | 0.000 | 0.00 |
| 闪烁（弱） | 0.392 | 5.96 |
| 闪烁（强） | 1.000 | 36.02 |
| 快速运动 | **0.000** | **26.98** |
| 平滑渐暗 | 0.005 | 2.68 |
| 噪点 | 0.007 | 9.08 |

"快速运动"一行是关键：帧差 26.98 会让原基线判为"重"，而正确答案是 0。

## 7. 标注轴的分歧

仓库 `main` 分支的 `build_course_labels.py` 采用 **O 轴（整体 MOS）**，
备选 T-all。本方案的 `make_labels.py` 采用 **T-5（stable/shaky）**。

任务书原文：「每个视频对应的 MOS 分数（该 MOS 分用于描述视频整体的
**时域一致性**）」「训练集中包含不同程度的典型的**闪烁**场景」。

O 与 T-all 都是综合质量维度，涵盖清晰度、噪声、压缩等与时域无关的失真；
T-5（stable/shaky）与 T-8（fluent/choppy）才是时域相关维度。

**若标注轴选错，训练目标就是错的，调参无法弥补。** 此项需向老师确认。

## 8. 使用方法

### 8.1 特征缓存（一次性，约 105 分钟 / 4543 个视频）

```bash
python3 scripts/extract_feats.py \
    --videos data/divide/videos \
    --out feats \
    --workers 3
```

可中断续跑：已存在的 `.npy` 会自动跳过。

查看计算量：

```bash
python3 scripts/extract_feats.py --flops
python3 scripts/extract_feats.py --flops --backbone r50
```

### 8.2 训练回归头（每次约 3 分钟）

```bash
python3 scripts/train_head.py \
    --feats feats \
    --train-labels data/divide/train_lable_train.txt \
    --val-labels data/divide/train_lable_test.txt \
    --agg mean \
    --out runs/o
```

消融实验：

```bash
for agg in mean mean+std mean+std+diff; do
  python3 scripts/train_head.py --feats feats --agg $agg --out runs/o \
      --train-labels data/divide/train_lable_train.txt \
      --val-labels data/divide/train_lable_test.txt
done

for br in all r50 vit; do
  python3 scripts/train_head.py --feats feats --branch $br --out runs/o \
      --train-labels data/divide/train_lable_train.txt \
      --val-labels data/divide/train_lable_test.txt
done
```

**注意：** 结果标签由 `分支_聚合方式` 构成，不含标注轴信息。
不同标注轴的实验必须用不同的 `--out` 目录，否则会互相覆盖。

生成结果表格：

```bash
python3 scripts/make_table.py --json runs/o/results.json
```

### 8.3 推理产出 score.txt

```bash
python3 scripts/predict_head.py \
    --videos data/test_videos \
    --ckpt runs/o/best_all_mean.pt \
    --out score.txt \
    --scale-0-100
```

所有配置（聚合方式、分支、片段划分、归一化参数）都从检查点读取，无需重复指定。
脚本会同时输出耗时与按任务书公式计算的扣分。

`--scale-0-100` 把预测值线性映射到 0~100，用于标注量纲为 1~5 时对齐
任务书的输出样例。线性变换不影响 SROCC 与 PLCC。

### 8.4 Web 界面

```bash
pip install gradio matplotlib
python3 scripts/app.py
```

浏览器打开 `http://localhost:7860`。

- **Single video**：上传视频 → 分数 + 抽取的帧 + 逐帧不稳定度曲线
- **Batch**：指定文件夹 → 生成 score.txt + 耗时统计

不稳定度曲线画的是片段内相邻帧特征差的均值，即 `diff` 聚合所依据的原始信号，
可用于答辩演示。
