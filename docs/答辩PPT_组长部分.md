## 三、P4 研究现状正文（组长 1.5 min）

**标题**：研究现状

**正文要点**（PPT 上按此精简，口播可展开）：

1. **任务定义**：输入任意长度/分辨率视频 → 输出 MOS 主观质量分。
   本课题聚焦**时域一致性**——闪烁、帧冻结、卡顿这类随时间变化的失真，
   静态图像质量方法（拿一帧看）天然看不见。
2. **技术路线**：手工特征回归（BRISQUE/VIDEVAL 时代）→ 深度单帧回归 →
   时空建模（Patch-VQ 时间拼接、ReLaX-VQA 残差层堆叠、DOVER 双视角）。
3. **本任务硬约束**：单视频 <300 G FLOPs；100 个测试视频 20 分钟时限
   （超时每分钟扣总分 0.01）；指标 SROCC/PLCC 越接近 1 越好。
4. **数据上的麻烦**：官方标注未随视频下发。我们从原版 MaxWell 仓库
   （VQAssessment/ExplainableVQA，ACMMM 2023）**重建了等效标注**——
   exemplar 分值与 CSV 整体 MOS 列 Pearson=1.0000，3634 训练 + 909 验证
   恰好覆盖全部 4543 个视频。官方标注到手后有一键校验脚本兜底。
5. **分工**（配右侧分工图）：整体打分主线（组长）+ 噪点/闪烁/模糊三类
   失真专项（组员各一人），经统一诊断接口 `diagnosis.py` 合成，
   最终汇总为 demo 系统 + 任务书格式 score.txt。

**图表**：右侧放 `docs/ppt_assets/division.png`（分工图）

**口播串词**（供参考，别背）：
"视频质量评估的难点在于主观——同一个视频有人打 3 分有人打 5 分，所以业界用
SROCC/PLCC 衡量排序一致性而非绝对误差。我们这次更特殊：重点考察时域失真，
官方标注又没发，所以我们从数据集原版仓库把标注重建出来了，并且验证了与
官方 CSV 的精确线性关系。"

## 四、P6 研究方法(1) 自研模型（组长 2 min，最重要的一页）

**标题**：研究方法(1) · 自研双分支模型与训练主线

**正文要点**：

1. **架构（任务书第五章逐维实现）**：
   ResNet-50 多尺度统计池化 13568 维 + ViT-B/16 token 统计池化 2304 维
   → 拼接 15872 维单帧特征 → T=8 帧 TSN 均匀采样时间平均 → 两层 MLP 回归 MOS。
   单帧 22 GFLOPs、8 帧共 176 G < 300 G 约束；实测推理 332 ms/视频。
2. **(A) baseline**：3634 视频监督训练（MSE），909 锁定验证集 →
   SROCC = PLCC = 0.6723。
3. **(B) 半监督伪标签循环**：每轮 N 次独立训练打分，**预测方差小**的未标注
   样本才进伪标签池（加权回训），OBJ = SROCC + PLCC 择优、连续无提升早停。
4. **v1 为什么失败**：伪标签有压缩偏差——模型"不敢打低分"，
   伪标签 std 0.422 < 真值 0.491，高权重回喂后 PLCC 单调下滑。
5. **v2 修复**：z-score 重标定（把伪标签分布对齐到真标注）+ 回喂权重
   0.5→0.2 + [1,5] 裁剪 → **轮次 2 OBJ=1.3457 反超 baseline（1.3446）**，
   SROCC 提升 0.017；轮 3/4 连续无提升，早停交付。
6. **一句结论**：伪标签的**分布对齐比数量重要**——v2 池子没变大，
   只改了分布，效果就反转了。

**图表**：右上放 `arch.png`（架构图），右下放 `semisup_v2.png`（轮次曲线）

**口播串词**：
"这是任务书规定的架构，我们逐维实现。半监督部分我想多说两句，因为它的
故事比数字有意思：v1 直接回喂伪标签，模型把自己保守的预测习惯也学回去了，
PLCC 一路下滑；v2 我们只做了一件事——把伪标签的分布重新标定到与真标注一致，
同样数量的伪标签，结果就反超了 baseline。这验证了机制有效，同时我们也承认：
0.0011 的 OBJ 提升在重复实验的噪声上界内，所以定位是'机制可行'而不是'大幅增益'。"

## 五、P7 研究方法(2) DOVER/DOVER++（组长 1.5 min）

**标题**：研究方法(2) · DOVER 复现与 DOVER++ 微调

**正文要点**：

1. **动机来自失败**：14 个训练集外视频排序对比，自研模型 9/11，
   真实内容上的闪烁/冻结排序失效；同源基线 DOVER 11/11 全对——
   问题不在打分能力，在**时域敏感度**。
2. **DOVER（ICCV 2023）双视角**：技术分支 Video Swin GRPB 用 7×7 碎片
   采样（对局部时序失真敏感）+ 美学分支 ConvNeXt。零样本直接可跑：
   SROCC=0.7110 / PLCC=0.7053（官方报告 0.7477/0.7546）。
3. **DOVER++ 微调**：官方训练框架 + divide_head 双标注头，课程数据上
   **仅微调头部 4 个 epoch** → SROCC=0.7854 / PLCC=0.7905，
   逼近官方全流程 0.8071/0.8126（那要全参数端到端，8 GB 显存上约 8.6 h/epoch）。
4. **工程可靠性**（一句话）：8 GB 显存被游戏/录屏挤爆触发过 4 次 GPU 硬错误
   → 我们给训练加了失败视频跳过、每轮落盘、resume.pth 断点续训，
   现在任何中断都能原地续跑。端到端阶段答辩前主动终止，**线性成果为交付状态**。
5. **交付**：微调权重已接入 demo，可现场和零样本/自研模型切换对比。

**图表**：右侧放 `doverpp_epoch.png`（epoch 曲线）

**口播串词**：
"我们的自研模型在真实内容上排序失效，复现了同数据集的官方基线 DOVER 后
差距立刻缩小。DOVER++ 最值得说的是成本：只动头部 4 个 epoch、约半小时，
就从 0.711 追到 0.785，剩下 0.02 的差距需要全参数训练几十个小时——
工程上我们选择了性价比高的那一段，并把它做成了可续跑的状态。"
